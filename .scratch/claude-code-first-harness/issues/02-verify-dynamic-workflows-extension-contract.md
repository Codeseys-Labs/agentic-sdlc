# Verify the current Claude Code Dynamic Workflows extension contract

Type: research
Status: resolved
Blocked by: none
Parent: [Find the path to a Claude Code-first Agentic SDLC product](../map.md)

## Question

Against current first-party Anthropic documentation and observable product surfaces, what can an
installable Claude Code harness distribute, configure, and verify around Dynamic Workflows? Cover
availability, storage and discovery, plugin integration, model and effort injection, tool access,
nesting and graph limits, persistence, identity evidence, versioning, and unsupported boundaries.

Asset: `../research/dynamic-workflows-extension-contract.md`

## Answer

[Dynamic Workflows extension contract](../research/dynamic-workflows-extension-contract.md)
finds that Claude Code can distribute namespaced, versioned workflow scripts and restrictive
agent roles through a plugin. The harness must version-gate the capability and run an executed
canary: plugin metadata and the workflow progress UI do not attest the effective provider, model,
route, or effort. Requested assignments, substitution warnings, and independent transport evidence
remain separate facts.
