# Install UX

Yes. The product split is coherent, with one important mise constraint:

> `mise use -g` installs **and globally activates** a tool.
> `mise --locked install` installs a checkout’s tools but does **not** make them globally active outside that checkout.

Making `mise --locked install` globally modify PATH or Claude Code configuration would require a hidden postinstall mutation. We should not do that.

## Recommended distribution contract

### 1. Primary quick install

```bash
mise use -g github:Codeseys-Labs/agentic-sdlc
```

This installs a versioned GitHub release artifact. Immediately afterward:

- `ccodex` is globally available anywhere mise’s global tools are active.
- `ccodex launch` and `ccodex ultracode` preserve the caller’s workspace.
- Runtime commands do not re-enter repository-scoped mise.
- The artifact contains the Agentic SDLC payload and its private runtime dependencies.
- No source checkout, `mise trust`, or contributor toolchain is required.

Claude Code activation remains explicit:

```bash
ccodex bundle install --agent claude
```

That second command is necessary because installing a mise tool and modifying `~/.claude` are different operations. It retains the existing collision checks, ownership records, dry run, status, and uninstall behavior.

### 2. Managed checkout

```bash
git clone https://github.com/Codeseys-Labs/agentic-sdlc.git
cd agentic-sdlc
mise trust ./mise.toml
mise --locked install
```

This remains the path for:

- customization and contribution;
- source-level inspection;
- repository gates and hooks;
- changing skills, policies, launchers, or tests;
- building release artifacts;
- running `mise run check`.

Once the first release artifact exists, the repository can pin that same GitHub tool in `mise.toml`. Then `mise --locked install` installs `ccodex` into the checkout’s mise environment. It does not globally activate it in unrelated directories; the global quick-install command owns that behavior.

## Release artifact shape

A single GitHub-backend tool cannot import the repository’s `[tools]` table or install transitive mise tools. The release therefore needs to be self-contained:

```text
agentic-sdlc-<version>-linux-x64.tar.zst
├── bin/
│   └── ccodex
└── libexec/agentic-sdlc/
    ├── assets/
    ├── agents/
    ├── commands/
    ├── policy/
    ├── scripts/
    ├── skills/
    ├── manifests/
    │   └── release.json
    └── runtime/
        ├── node/
        ├── python/
        ├── jq/
        ├── opencodex/
        ├── seeds/
        └── mermaid/
```

`ccodex` should resolve `libexec/agentic-sdlc` relative to its own installed location. It must not contain an absolute checkout path like the current template does at `assets/launchers/ccodex.in:38-45`.

Version upgrades then become ordinary mise operations. Versions live side by side in mise’s store, so rollback means selecting the earlier release again. `ccodex` should not grow a second self-updater.

## Runtime versus contributor tooling

The quick artifact should contain only runtime necessities:

| Capability | Quick artifact | Managed checkout |
|---|---:|---:|
| `ccodex` | Yes | Via pinned release tool |
| Agentic SDLC skills/agents/commands | Yes | Source tree |
| OpenCodex | Private pinned runtime | Existing mise pin |
| `jq` | Private pinned runtime | Existing mise pin |
| Python 3.12.11 | Private runtime | Supplied through uv |
| Seeds and Bun | Private pinned runtime | Existing mise pins |
| Mermaid CLI packages | Private pinned runtime | Existing lock/provisioner |
| `uv` | Not needed at daily runtime | Yes |
| lefthook, betterleaks | No | Yes |
| `gh`, ripgrep, fd | No | Yes |
| repository tests and gates | No | Yes |

Bundling Python directly lets release-mode `ccodex` run the stdlib lifecycle scripts without carrying uv and without downloading Python on first use. Managed checkout operations should continue using uv.

## Mermaid CLI

Do **not** restore this entry to `mise.toml`:

```toml
[tools."npm:@mermaid-js/mermaid-cli"]
```

The repository already proved why that fails:

- Puppeteer’s postinstall downloaded an uncontrolled browser.
- A clean minimal installation failed without `unzip`.
- The browser landed outside the reviewed runtime digests.
- The current protection is encoded in `mise.toml:47-56` and `docs/adr/0002-mise-is-the-single-front-door.md:110-160`.

Instead:

1. Build the release’s Mermaid `node_modules` using the existing `package-lock.json`.
2. Use `npm ci --ignore-scripts`, matching `scripts/provision_mermaid_linux.py:131-139`.
3. Include the pinned Mermaid CLI package in the release.
4. Keep raw `mmdc` private rather than exposing it on PATH.
5. Add a supported route such as:

   ```bash
   ccodex mermaid render <definition> <output.svg>
   ```

6. Preserve the existing sandboxed renderer and sanitizer.

The pinned browser is approximately 358 MiB, while current Mermaid `node_modules` is approximately 446 MiB. Including both makes a “quick” artifact very large. The sensible initial boundary is:

- Mermaid CLI packages are installed with the quick artifact.
- The browser remains an explicit, digest-checked provision step.
- Certified rendering remains Linux x64 only until macOS and Windows receive equivalent sandbox and provenance evidence.

That is more honest than silently shipping an uncertified cross-platform renderer.

## Git and curl

Git and curl should be **required host capabilities**, not silently bundled.

There is no stable ordinary mise registry entry for either command in the current registry. Mise’s `pkgx:` backend could theoretically supply them, but it is experimental and would add another package ecosystem and transitive runtime model. Bundling Git also introduces platform-specific TLS, credential-helper, CA-store, and system-configuration concerns.

Add a read-only preflight:

```bash
ccodex doctor
```

It should verify, at minimum:

- supported OS and architecture;
- `git` available and executable;
- `curl` available and executable;
- `claude` available for launch routes;
- packaged OCX, jq, Python, Seeds, and Mermaid identities;
- writable lifecycle state directory;
- Claude host-plane collision status.

`ccodex bundle install` should run that preflight before changing host entries and refuse with named remediation if Git or curl is missing.

We can later eliminate curl from the trusted gateway path by using bundled Python’s HTTP standard library for loopback health and catalog requests. Curl would remain a readiness capability rather than an unpinned route-integrity dependency.

## Activation and upgrades

Quick-install lifecycle:

```bash
mise use -g github:Codeseys-Labs/agentic-sdlc
ccodex doctor
ccodex bundle install --agent claude
ccodex launch
```

Upgrade lifecycle:

```bash
mise upgrade github:Codeseys-Labs/agentic-sdlc
ccodex bundle install --agent claude
```

The second command explicitly refreshes owned host entries. Quick-install activation should use **copies**, not links into a version-specific mise directory. Otherwise `mise prune` could remove an old version and break Claude’s linked skills. Managed checkout can retain symlinks because source editability is the point of that path.

For reproducibility, document the exact-version form alongside the convenience path:

```bash
mise use -g github:Codeseys-Labs/agentic-sdlc@<version>
```

The unversioned command intentionally follows the release marked latest; it is not equivalent to the repository’s locked installation.

## Pre-release candidate placement (current bridging step)

> **SUPERSEDED IN PART, 2026-08-25 (agentic-sdlc-7a2b, wave W3b).** The `write_acquisition_receipt.py`
> invocation below is retired: `ccodex install --scope user --agent <claude|codex>` now AUTO-SEALS the
> acquisition receipt itself when the acquisition layout holds a release root and no receipt yet. It
> verifies the root against its own `manifest.json` in both directions and calls that module's own seal
> path, so the bytes are identical to what the command below would have written; a second install of the
> same archive reuses the filed receipt instead of sealing a second one, and a receipt whose bytes
> disagree with their own seal is refused rather than replaced. `ccodex install … --dry-run` reports the
> ticket it WOULD seal and writes nothing.
>
> **The PLACEMENT is not retired, and this section is kept for it.** The three shell steps that extract
> the archive to `…/candidates/<digest>/root` still stand, because a release root carries no statement of
> the digest of the archive it was extracted from — the manifest is inside the tarball and cannot name the
> tarball's own hash — so the layout's directory name is the only surviving record of that fact, and the
> acquisition receipt is keyed by it. The design plan
> (`docs/plans/2026-08-25-front-door-unification.md` §3.3, §3.5) says auto-seal *deletes* this recipe;
> that overstates it by exactly one command, and `docs/research/2026-08-24-install-ux-corpus/critique-a.md`
> §2.1 obstacle 1 verified why before the plan was ratified. Re-pointing root admission at a
> mise-resolved tree remains open and is not W3b's.
>
> This paragraph is dated evidence about a transition. The section below is left in its original words.

Until a GitHub release asset exists, the acquire leg runs locally against the archive
`mise run release:build` writes to `dist/`. `ccodex sdlc install` and `update` resolve a candidate
root from the acquisition layout alone, and `scripts/write_acquisition_receipt.py` refuses any
other placement, so place the archive exactly here:

```bash
digest=$(sha256sum dist/agentic-sdlc-<version>.tar.gz | cut -d' ' -f1)
candidates="${XDG_DATA_HOME:-$HOME/.local/share}/agentic-sdlc/acquisition/candidates/$digest"
mkdir -p "$candidates"
tar -xzf dist/agentic-sdlc-<version>.tar.gz -C "$candidates"
mv "$candidates/agentic-sdlc-<version>" "$candidates/root"
uv run --python 3.12.11 --script scripts/write_acquisition_receipt.py \
  --root "$candidates/root" --state-home "${XDG_STATE_HOME:-$HOME/.local/state}" \
  --archive dist/agentic-sdlc-<version>.tar.gz
```

The archive’s own sha256 names the parent directory, its `agentic-sdlc-<version>` top level becomes
`root`, and `manifest.json` is already inside — the receipt writer re-hashes every entry against it
before sealing the receipt under `$XDG_STATE_HOME/agentic-sdlc/acquisition/receipts/`. This is a
bridging step, not part of the contract above: when the install/update verbs are next touched,
re-point their receipt and root admission at the mise-resolved root and retire the layout
constraint, deleting this section with it. A sealed receipt is evidence that a placed root was
verified against its manifest; it is not an installation, a release, or a support claim.

## Current feasibility evidence

- The requested command currently fails because the repository has **zero GitHub releases and zero release tags**.
- With repository locking removed from the probe, mise reports:
  `no versions found for github:Codeseys-Labs/agentic-sdlc`.
- The GitHub backend supports exactly the needed archive shape: platform asset autodetection, archive extraction, `bin/` discovery, checksums, and attestations.
- It does **not** consume the repository’s `[tools]` or install those tools transitively.
- Current release payload source is small, about 2.3 MiB; the runtime dependencies, especially OCX and Mermaid, dominate distribution size.
- No repository files, global mise configuration, host activation state, release, or installation were changed during this feasibility pass.

`★ Insight ─────────────────────────────────────`
The release archive becomes the stable installed “distribution root.” That removes the accidental coupling between daily use and a mutable contributor checkout, while copied host activation prevents mise version pruning from breaking Claude’s configured skills.
`─────────────────────────────────────────────────`

**DONE_WITH_CONCERNS:** the architecture is feasible, but the first supported quick-install release should be Linux x64/WSL unless equivalent Mermaid and operator-tool certification is completed for macOS and native Windows.
