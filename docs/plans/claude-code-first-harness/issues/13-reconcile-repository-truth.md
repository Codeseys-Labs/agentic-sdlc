### Reconciliation verdict

Preserve and compose the current safety substrate. The repository already has strong lifecycle
ownership and recovery, external-library isolation, Seeds custody, worktree and fan-in doctrine,
route evidence, rightsizing, Mermaid, gates, and focused adversarial tests. Replacing those
subsystems would add risk without completing the product.

The missing product layer is:

- a versioned mise release and `ccodex sdlc` lifecycle;
- an owned native-Claude Dynamic Workflow and one executable Core journey;
- immutable mission, plan, diff, drift, and bounded-auto artifacts;
- a unified local observability and receipt projection;
- `ccodex routes` for the optional routed-model profile; and
- the selected documentarian, draw.io, and threat-modeling capabilities.

Current public claims are contradictory. `VISION.md` says Claude Code is primary, while the README,
root agent instructions, plugin manifests, and marketplace descriptions lead with a provider-native
multi-host product. The specification must define the executable replacement and one claim-linting
migration; documentation must not run ahead of implementation.

The existing Seeds queue is historical roadmap evidence, not current product truth. Several open
PRIME/gateway records conflict with both current code and the adopted native-Claude Core plus
optional routed-model profile. This audit does not mutate them. A later authorized reconciliation
must preserve history and classify each as still valid, satisfied but stale, superseded, or a
migration source.

Proceed to significance-gated ADR recording, then assemble the `/to-spec` handoff around the
native-Claude tracer-bullet journey. Exact Claude Code stable/latest versions remain test references;
minimum feature requirements plus current capability admission govern compatibility and create no
hard maximum.
