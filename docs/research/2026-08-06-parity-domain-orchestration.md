## (1) The three most consequential gaps

1. **No enforced budget/depth ledger backing the mission loop's numeric claims.** `references/mission-loop.md:48-59` and `commands/sdlc-mission.md:31,39-41` state exact numbers (WIP caps, backflow pass ceilings, delegation depth ≤2) that read as operational guarantees, but nothing in `skills/agentic-sdlc/tools/` or `scripts/` counts a live worker, decrements a budget, or refuses a spawn past a cap — confirmed by `rg -ln "WIP|wip_cap|delegation_depth|backflow" scripts/ skills/agentic-sdlc/tools/` returning zero hits. `pi-dynamic-fractal-workflows/src/frame-ledger.ts` (598 lines) is a directly portable, MIT-licensed, extensively tested (`tests/frame-ledger-unit.test.ts`, `frame-ledger-wiring.test.ts`, `fractal-depth.test.ts`, ≈40+ combined cases) reference implementation of exactly this: no-superset child grants by construction (`createChildLedger`, line 290), a depth cap the caller cannot raise, and a wind-down-reserve landing threshold. The harvest memo's item #19 already names porting the no-superset invariant + wind-down reserve as backlog, but it remains unactioned. **Smallest closing change**: port `frame-ledger.ts`'s pure, dependency-free functions (no I/O, no `await`) as a Python module under `skills/agentic-sdlc/tools/`, wire it to record delegation-depth and worker counts as the mission-loop's own tracking artifact (not to gate the host's native Task tool, which agentic-sdlc cannot instrument), and have the conductor consult it before each dispatch — turning "≤2 nesting" from a doc-lint assertion into an actual counter the conductor reads.

2. **No fail-closed worktree-isolation test suite for concurrent-agent dispatch (as opposed to Seeds-bootstrap isolation).** `skills/agentic-sdlc/references/worktree-failclosed-tests.md` is explicit and honest that it is "a specification... nothing here is executable," but this means the domain's single most safety-critical failure mode — a dispatcher silently running a "worktree-isolated" agent in the shared checkout instead of refusing — has zero test coverage in this repo today, while the sibling project's `tests/worktree-isolation-failclosed.test.ts` (374 lines, 18 planted-violation cases: occupied branch, non-git cwd, throwing observer, mid-flight abort, timeout) is a ready-made, already-executed template. **Smallest closing change**: since agentic-sdlc has no bundled dispatcher of its own to test (it delegates fan-out to the host's native Task tool), the achievable analog is a Python test that plants the git-level preconditions (occupied branch name, dirty/non-git target dir) against `commands/sdlc-wave.md`'s prescribed `git worktree add` invocation pattern and asserts the shell command itself fails closed (non-zero exit, no orphaned branch) — narrower than the sibling's dispatcher-level test, but it would convert one entry in the 227-line spec from "designed" to "shipped" rather than porting all of it at once.

3. **Seeds mutation remains read-only, so the mission loop's own "seeds-first, no-inline-fixes" rule cannot execute end-to-end.** `references/mission-loop.md:34-46` ("Discoveries NEVER get fixed inline. Return a seed-shaped recommendation first... the conductor is the sole queue writer") is the load-bearing rule the entire mission doctrine depends on, but `skills/agentic-sdlc/tools/seeds-launcher.mjs`'s argv grammar (confirmed via direct read of `docs.../seeds-worktrees.md:44-45`, "permits precisely `--version`, `prime`, `ready [--format json]`, and `blocked [--format json]`") admits no `create`/`update`/`close`/`dep` verb at all. A conductor following the mission loop's own instructions today has nowhere to durably record a classified finding except an external, unversioned mechanism the doctrine explicitly forbids treating as authoritative. **Smallest closing change**: this is the harvest memo's own #3 backlog item, already correctly scoped — add the minimal `sd·create`/`sd·update` mutation seam with the same CAS/readback discipline `activation-planner.py` already demonstrates for PRIME apply, rather than inventing a new pattern.

## (2) Original invention: neither source nor pi-lab prescribed it

- **The `RuntimeAssignment` `resolved`/`inherited`/`unresolved` tri-state gating dispatch inside every loop-phase command** (`sdlc-frame.md:22-28`, `deep-work-loop.md:54-72`, `tiered-orchestration.md:13-33`) is agentic-sdlc's own invention layered onto the loop doctrine — pi-lab's closest analog (`right-sizing-design.md`'s three-provenance-class route-qualification scheme) governs which model is eligible for a role, not whether a dispatch is permitted to proceed at all pending adapter readback. This is **load-bearing** within agentic-sdlc's own doctrine (every command file repeats it as a hard stop-before-dispatch condition) but remains **unenforced in code** — original invention at the doctrine layer, speculative as an actual control, since no runtime resolves or verifies model identity anywhere in this repo.
- **The "concurrent critique team audits stable (squash-merged) snapshots, never live worktrees" rule** (`mission-loop.md:61-69`, `commands/sdlc-mission.md:33-36`) has no direct source-corpus antecedent found in this session — pi-lab's critique mechanisms (competitor teardowns, ADR review) operate on a fixed artifact, not a continuously-refreshing standing background reviewer racing a live wave. This is a genuinely novel operational pattern; it is **speculative** rather than load-bearing today, since no test or tool exercises "audit a stable snapshot while a wave is still running" as a real mechanic — it exists only as a paragraph of guidance.
- **The evidence-class citation-verification rule** ("Verify every reviewer citation before acting on it... check the file exists and the line says what was claimed," `deep-work-loop.md:145-148`) is stated as an operational-discipline rule inside the loop reference rather than sourced from pi-lab's `evidence-discipline` house skill (which governs classifying evidence, not verifying a specific `file:line` citation mechanically). This is a real, specific, actionable rule with no direct source; it is **load-bearing in intent** (this very review followed it) but enforced only by convention — the rule itself admits "a citation-checking script narrows the search; it does not replace a human spot check."

## (3) Shipped-doc-claims-a-capability-the-code-lacks, specific instances

- **`commands/sdlc-mission.md:31`** states WIP caps as an operational fact ("WIP caps: impl ≤3, research ≤2, integration ≤1, critique ≤1, nesting ≤2") in the imperative voice of a runbook step, indistinguishable in tone from step 5's Seeds-priming instruction that does correspond to real (if read-only) tool behavior. A reader following this command literally has no mechanism to check whether "≤3" is currently true — there is no counter, no query, nothing in `skills/agentic-sdlc/tools/` that reports current WIP.
- **`commands/sdlc-mission.md:39-41`** ("Backflow... within budgets (global passes ≤6; Frame ≤1, Discover/Research/Plan ≤2, Act ≤3 re-entries)") — same pattern: specific integers presented as governing constraints with no corresponding counter anywhere in the codebase. `tests/test_deep_work_loop.py` and `test_authority_corrections.py` only assert that the sentence containing these numbers exists in the markdown, not that any run has ever been bounded by them.
- **`references/mission-loop.md:56`** ("Delegation nesting depth ≤ 2") is asserted with the same declarative confidence as `pi-dynamic-fractal-workflows/src/config.ts`'s depth cap, but the latter is backed by `DEPTH_CAP_EXCEEDED` as an actual thrown, non-retryable error (`workflow-tool.ts:39`) while the former has no corresponding refusal path — a reader cannot distinguish, from the document alone, that one number is enforced and the other is aspirational.
