# Feature-by-feature capability review of agentic-sdlc vs pi-lab, judged against the source doctrine held in BOTH projects. Read-only. Focus: pi-lab CAPABILITY SURFACE (what it built, what it admits it did not) via README, package.json, src/ (40 .ts files), profile/, 22 SKILL.md, docs/assessment/{20260727,20260730}/, docs/dogfood/, and capability-map.md; cross-referenced against agentic-sdlc's own shipped surface (8 skills, 7 Claude agents, 4 commands, 4 tools, 14 references, 23 test files) and its 12 research memos (esp. the harvest memo, which already owns the port-back backlog and is not re-derived here).

## 0. Headline verdict

pi-lab is a *runtime-specific installer/setup-tool laboratory for the `pi` agent CLI*, built with an unusually rigorous self-audit culture — and that same culture's own 2026-07-27 adversarial self-critique (`docs/assessment/20260727/assess-self-critique.md`) concludes the audit apparatus has become "a substitute for shipping": a 4.5:1 (now re-measured ≈4.6:1) doc-to-code ratio, 233/259 open Seeds issues at assessment time, and a single install receipt that changed nothing (`"adds": []`). agentic-sdlc is a *host-agnostic Agent-Skills bundle* (doctrine + tools, no installer-of-a-third-party-runtime) with a much smaller absolute footprint but a materially higher SHIPPED:DESIGNED ratio inside the surface it actually claims. Neither project has run its own flagship end-to-end delivery loop on a repo it doesn't own (pi-lab: `assess-delivery-plane.md` §2.11, "the SDLC wave has never been framed and never run"; agentic-sdlc: PRIME apply/verify/recover is unexposed externally and Seeds mutation is read-only per `docs/research/2026-08-05-pi-lab-harvest-memo.md` §1).

## 1. Install/activation lifecycle (plan→apply→receipt→reverse)

**pi-lab SHIPPED, with tests, but empirically near-vacuous in practice.** `src/commands/install.ts`, `src/core/live-profile.ts`, `src/core/receipt-vouch.ts` implement a genuine transactional plan→digest→apply→receipt→reversible-uninstall engine: key-level (not file-level) settings ownership over 4 allowlisted keys (`packages`, `defaultProvider`, `defaultModel`, `defaultThinkingLevel`), union-merge for lists, multiset-aware element-wise reversal, and receipt-vouching that re-derives reversal authority from the *current* reviewed manifest rather than trusting the receipt's own claims (closes two reproduced forged-receipt exploits per the harvest memo). BUT: `manifests/profile-recommended.json#defaults` is `{}`, so `resolvePayload` returns exactly `{packages}` and copies zero files (`capability-map.md` §a: "install writes one key... no provider is set, no model is set, no effect ceiling is applied"). The one real install receipt on the operator's own host recorded `"adds": []` — byte-identical to pre-existing state (`assess-delivery-plane.md` §6.3, §7.1-7.2). `doctor` returns `unhealthy` and exits 0 (not a gate). The 2026-07-31 two-foreign-projects dogfood run (`docs/dogfood/2026-07-31-two-foreign-projects.md`) is the one genuine external exercise: greenfield + brownfield clones, isolated HOME/XDG, six provoked refusals all exit 2 with self-naming remedies, byte-for-byte reversal — real evidence, but found new defects (doctor's `pi --version` probe can't see a broken agent; `--bootstrap-pi` silently no-ops).

**agentic-sdlc:** SHIPPED at the plan layer, and fuller than the harvest memo implies. `skills/agentic-sdlc/tools/activation-planner.py` (2,948 lines) is a hardened transactional engine — statx/fcntl, single-use grants, exact-tuple validation, tested via `tests/test_activation_planner.py` + `tests/test_activation_transaction.py` + `tests/test_prime_candidate_custody.py`. Its CLI (`activation-planner.py:2926-2935`) exposes `plan`, `apply`, `status`, and `recover inspect|<decision>` subcommands — i.e., apply/status/recover ARE present in code (correcting the harvest memo's summary that only `plan` is exposed; the memo's own §1 caveat hedges with "reportedly" — this review's direct read of the argparse table resolves the hedge: the CLI surface is fuller than implied). What is NOT present is any dogfood run analogous to pi-lab's 2026-07-31 artifact — no equivalent evidence file exists in agentic-sdlc's docs/progress/ tree for an external-repo activation. `SESSION-HANDOFF.md` (uncommitted) records this as the acknowledged #1 blocking gap ("agentic-sdlc-p1: Execute Complete PRIME slice" is the sole ready Seeds issue).

**Verdict:** pi-lab's engine is more battle-tested (real reproduced exploits closed, one real external dogfood run) but its payload is empirically empty; agentic-sdlc's engine has a richer CLI surface (apply/status/recover all present) but zero external-repo dogfood evidence of its own. Neither should claim "used successfully on someone else's repo" today.

## 2. Doctor/drift-detection and reversibility

**pi-lab SHIPPED with a genuinely observed positive result.** `doctor` (`src/commands/doctor.ts:1,19`) reads the live profile via `installStatus` and, per `assess-delivery-plane.md` §7.1, DID detect a real unapproved hand-edit twice, out-of-process, recorded in `~/.local/state/pi-lab/live-meter.jsonl` — "the closest thing the delivery plane has to a control observed doing its job on live state." But its remedy path is a documented dead end on the `drifted` state (deletes the receipt without repairing anything, §7.2), and it exits 0 even when `unhealthy`, so it cannot gate a script.

**agentic-sdlc:** the activation-planner's `status`/`recover inspect` path is the doctor-equivalent, backed by unit tests, but (per above) has no observed real-drift-detection instance recorded anywhere in the repo's evidence trail — DESIGNED-and-unit-tested, not yet field-observed the way pi-lab's is.

## 3. Checkpoint / restore

**pi-lab SHIPPED a deliberately narrow, doctrinally justified absence.** ADR-0002 ("pi-lab does not restore; git restores") + its 2026-07-30 amendment is one of the strongest pieces of engineering doctrine in either repo: `checkpoint capture`/`verify`/`list` exist, are read-only-proven (mutates nothing but its own ledger file, `src/commands/checkpoint.ts:34`), and `list` prints the exact `git worktree add ... <sha>` command an operator would run rather than reimplementing restore (`src/core/checkpoint-list.ts:96`). The kill criterion ("nobody ever went on to restore") is metered via `restore-plan` ledger ops (`src/core/checkpoint-record.ts:96,256`) rather than asserted. SHIPPED, tested (checkpoint-adversary test suite, 5 tests observed running 1.0-1.7s against a 5000ms ceiling).

**agentic-sdlc:** has no dedicated checkpoint subsystem; `commands/sdlc-mission.md:43` and `references/mission-loop.md:100` mention "final checkpoint" only as a doctrinal step in the mission loop narrative (evidence + backlog state + tracker-clean), not as a code artifact with its own ledger, commands, or tests. **ABSENT as a shipped mechanism; DESIGNED only as prose inside the mission loop.** This is a genuine capability pi-lab has that agentic-sdlc lacks, and it is exactly the shape (git-native, restore-refused, ledger-metered) that would fit agentic-sdlc's own doctrine — not currently on the harvest memo's port-back list as a discrete item (the memo's items #7/#22/#23 touch adjacent receipt/cost mechanics but not checkpoint/restore itself).

## 4. Secrets/gate scanning

**pi-lab SHIPPED, unusually rigorous.** The secrets stage (ADR-0006, ADR-0009) qualifies the scanner *artifact* itself before running it (prints absolute path/semver/SHA-256, refuses an unrecognized version, exit 78 `SCANNER_COVERAGE_GAP`/`78` distinct from findings=1/clean=0/timeout=75), and the path set is *derived* from `RELEASE_PAYLOAD` rather than a hand-maintained list that (per ADR-0009) previously omitted 209 of 849 tracked files. BUT per `assess-delivery-plane.md` §2.9: **no lefthook hook is armed anywhere in pi-lab, and pi-lab has zero CI** — the gate that exists is unreachable from a real push/PR event. `mise run check` is also load-flaky under concurrency (§6.4: 127/0 idle vs 117/10 under wave load — "the *variance* is the defect").

**agentic-sdlc:** `skills/repo-toolchain-gates/SKILL.md` + `mise.toml` wire betterleaks/gitleaks as an advisory-tier convenience (not gate-load-bearing per AGENTS.md's mise doctrine), and `tests/test_gate_graph.py` + `tests/test_gate_receipts.py` assert the wiring matches doctrine with negative fixtures (`LOCKED_TOOLCHAIN`/`TOOLCHAIN_MUTATIONS` per the harvest memo §5's OOTB tooling section). agentic-sdlc DOES have `lefthook` pinned in `mise.toml:17` and `hooks:install` in AGENTS.md's install verb list; its own AGENTS.md is explicit that hooks are "best-effort convenience, not release authority," i.e. it does not overclaim gate status the way pi-lab's own doc/CI gap contradicts its emphasis-inverted ADR ("CI workflow is PRIME's primary gate deliverable" with zero CI in the repo that wrote that sentence). **Verdict: pi-lab's secrets-artifact-qualification design is more sophisticated than anything in agentic-sdlc, but pi-lab's own hook/CI enforcement is measurably absent where it claims priority; agentic-sdlc's gate claims are narrower but not self-contradicted by its own evidence.**

## 5. Multi-model / route delegation

**pi-lab: strong DESIGNED layer, admitted non-distributable.** Nine SDLC roles in `pi-agentic-sdlc-skills` bind a model AND a tool allowlist per role across 3 provider lanes (frontmatter table reproduced in `assess-delivery-plane.md` §2.1) — read-only roles (reviewer, critic) genuinely carry no write tool, which the assessment calls "ADR-0001's replacement promise being honoured in the payload." BUT the live 16-tier route map that every "right-sized route per slot" claim depends on is a hand-placed file with zero code consumers, zero tests, zero installer (`grep -rn "variants/deep-work" src/ scripts/ tests/` → zero hits); the version that WOULD ship via `src/core/profile.ts:79` is a 3-tier sonnet-only stub. "The multi-model delegation tenet is not distributable at all today" (§2.1 verdict). A route ledger (`docs/route-ledger/route-ledger.json`) does empirically qualify 16 routes across 2 lanes with positive/negative/unprobed status — real evidence-based route qualification discipline, but it has drifted from the live tier map it claims to project (a 3rd lane, `bedrock-mantle-messages`, has 3 live tiers and zero ledger records).

**agentic-sdlc SHIPPED, and stricter than pi-lab's design.** `skills/model-tier-rightsizing/SKILL.md` + `policy/runtime-assignment-receipt-v1.json` + `scripts/receipt_admission.py`, tested by 22 test functions in `tests/test_model_tier_rightsizing.py`, implement the `resolved`/`inherited`/`unresolved` distinction as an enforced contract (`resolved_provider`/`resolved_model_id`/`model_readback_status: verified` required fields, `model-tier-rightsizing/SKILL.md:58-90`) rather than prose. AGENTS.md states this as immutable doctrine ("Requested, inherited, unresolved, or incomplete assignments stop before dispatch"). This is agentic-sdlc's single strongest capability relative to pi-lab's own admitted-non-distributable route map — the harvest memo (item #9, #10) correctly identifies pi-lab's route-ledger provenance-class vocabulary (declared/mined/observed; a benchmark score never fills a scale-setter slot) as still worth harvesting to harden agentic-sdlc's schema further, which is accurate and not yet done.

## 6. Dynamic multi-agent workflow engine (fan-out, budget ledgers, recursion cap)

**pi-lab-adjacent (pi-dynamic-fractal-workflows, a sibling repo, not pi-lab itself) SHIPPED and real**, per capability-map.md §(b)(1): bounded fractal depth with per-frame immutable depth cap (default 3/ceiling 5), a token/agent ledger wired end-to-end (`child grant = min(levelCap(depth), parentAvailable)`), 35 real workflow-run records, 1,198 regression tests. This is the most mature asset in the entire pi ecosystem per the map. BUT it is loaded into the operator's live profile by hand-edit (a relative local path, not through any pi-lab install), pinned by nothing pi-lab installs — the exact same "designed-but-not-distributable" pattern as §5's route map.

**agentic-sdlc:** has no analogous *runtime* fan-out engine of its own (it is a doctrine/skill bundle, not a workflow-execution runtime) — this is a category difference rather than a gap: agentic-sdlc's "tiered orchestration" (`references/tiered-orchestration.md`, `references/deep-work-loop.md` — 222 lines) is host-delegated (Claude Code's own Task tool / subagent mechanism executes the fan-out; agentic-sdlc supplies doctrine, role bindings, and evidence contracts on top). The harvest memo's item #19 (port the frame-ledger's no-superset invariant + wind-down reserve as a formalization of agentic-sdlc's "bounded delegation depth" prose) is accurate and unactioned — agentic-sdlc's bounded-depth claim remains DESIGNED (prose) where pi-dynamic-fractal-workflows has an executable, tested ledger enforcing it.

## 7. Worktree isolation / fail-closed testing

**pi-lab SHIPPED a genuinely good but narrow shell-script mechanism.** `docs/workstream-isolation.md`: three named refusals (dirty-worktree refusal, `merge --ff-only` after rebase, `drop` refuses unmerged commits), each protecting a loss already suffered. Honest about its own convenience-not-guarantee scope ("best-effort: if the directory is not a git repo it logs `isolation ignored` and continues without isolation"). BUT it is a shell script (`scripts/ws-worktree.sh`) that only pi-lab has, with an open P1 seed demanding it become a product feature rather than a helper — nothing in pi-lab's install payload carries it to a target repo (§2.7 score: 2/5).

**agentic-sdlc SHIPPED with an explicit test-pattern reference.** `skills/agentic-sdlc/references/worktree-failclosed-tests.md` (227 lines) plus `skills/agentic-sdlc/references/worktree-integration.md` and `seeds-worktrees.md` document doctrine; `tests/test_seeds_launcher.py` (877 lines, 18 test functions covering bootstrap tuple validation, dirty/untracked distribution rejection, wrong-Node-process rejection, ambient config isolation) is a real, dense adversarial test suite — though it is about the Seeds *distribution bootstrap*, not directly about worktree fan-out isolation per se. The harvest memo's item #11 correctly flags that pi-dynamic-fractal-workflows' `tests/worktree-isolation-failclosed.test.ts` (planted-violation tests per failure mode: occupied branch, non-git cwd, throwing observer, mid-flight abort, timeout) is a ready-made template agentic-sdlc has not yet adapted — so agentic-sdlc's worktree fail-closed *test coverage specifically for concurrent-agent worktree isolation* (as opposed to Seeds-bootstrap isolation) is currently DESIGNED (the reference doc) rather than SHIPPED-with-a-matching-test. This is a real, currently-open gap correctly identified by agentic-sdlc's own prior research and not yet closed.

## 8. Skill library / house doctrine (evidence discipline, loop design, context budget, repo hygiene, skill authoring)

**pi-lab SHIPPED all five `skills/house/*` skills, deliberately kept OFF the install payload and off Pi's load path (ADR-0008)** because Pi eagerly indexes every loaded skill's description into every turn's system prompt — a measured real cost, not an assumption. This is a genuinely useful piece of prior art: pi-lab chose to author high-quality doctrine skills and then NOT ship them by default, a distinction agentic-sdlc's own AGENTS.md doesn't yet have an equivalent formalized rule for (its skill-selection-budget concern is implicit, e.g. in the harvest memo's repeated "check overlap against already-installed global skills before shipping" caveats for the diagrams family, items #38/#39, but ADR-0008's explicit token-cost measurement is not itself replicated in agentic-sdlc as a stated policy).

**agentic-sdlc:** has no direct 1:1 equivalent skill for evidence-discipline/loop-design/context-budget/repo-hygiene/skill-authoring-standard as *standalone skills* — but a directory listing this session confirms `skills/agentic-sdlc/references/evidence-discipline.md` already exists, contradicting the harvest memo's own port-back item #5 framing it as "new reference to be created" — the file exists; this review did not perform a byte-level content diff against `pi-lab/skills/house/evidence-discipline/SKILL.md` (out of scope for this pass), so whether its 5-class vocabulary + anti-inflation rule content matches is unconfirmed and flagged as the next concrete check for the orchestrating agent.

`skills/agentic-sdlc/references/deep-work-loop.md` exists at 222 lines vs the harvest memo's cited comparison of "91 vs pi-agentic-sdlc-skills' 240-line deep-work-mega-loop/SKILL.md" — the memo's 91-line figure is now STALE against the current 222-line file (confirmed via `wc -l` in this session), meaning agentic-sdlc has already grown this reference substantially since the memo was written (two post-memo commits, `a0baefd` "consolidate bounded deep work loop doctrine" and `f4fef2f` "enforce subject-agnostic loop authority guard", both touch exactly this subject matter). The harvest memo's port-back item #4 (16 incident-backed rules + 4-cause empty-agent-result taxonomy) should be re-diffed against the current 222-line file before being treated as still-open at its originally measured size.

## 9. Mermaid / diagram tenet

**pi-lab: SHIPPED as a skill library, but DESIGNED-and-abandoned in practice for pi-lab itself.** `skills/diagrams/` ships 8 SKILL.md files (a router + diagram-as-evidence + 6 mermaid deep-dives covering all 31 mermaid diagram types) — real content. BUT pi-lab's own self-assessment (`assess-delivery-plane.md` §2.8, tenet score 0/5): zero rendered mermaid diagrams anywhere in pi-lab itself; `mmdc` is installed and invoked by no task/gate/CI. "The tenet was practised exactly once, by hand, in four files of the predecessor repo."

**agentic-sdlc:** mermaid appears only inside research-memo prose (`docs/research/2026-08-05-docs-commits-skills-spec.md`, `2026-08-05-pi-lab-harvest-memo.md`, `2026-08-05-restructure-design-plugin-first.md`) and one model-routing-calibration reference — **ABSENT as a shipped skill or diagram library**, and the harvest memo's own item #38 correctly flags this as a possible future skill contingent on checking overlap with the already-installed global `diagram`/`dataviz` skills (which this session confirms ARE present in the calling environment's skill list). **Correction/addition to the memo's framing:** since global `diagram` and `dataviz` skills are confirmed available in the orchestrating environment, porting pi-lab's mermaid family would likely fail the "beat the incumbent, don't duplicate" bar pi-lab's own capability-map §(c) states for new extensions — this review agrees with the memo's "low priority, check overlap first" verdict and adds that the overlap check now has a concrete answer (global skills exist) rather than being hypothetical.

## 10. jj (Jujutsu) VCS support

**pi-lab: DESIGNED-and-explicitly-blocked.** Installed on the host, zero colocated repos, the workstream implementing it is ledgered `DO NOT SHIP` on an unmerged branch (`assess-delivery-plane.md` §2, tenet 10, score 1/5).

**agentic-sdlc: explicitly and deliberately ABSENT by design, stated cleanly.** `skills/agentic-sdlc/references/jj-vcs.md` (4 lines, confirmed via Read): "This is a one-release refusal pointer... This release refuses all alternate VCS operations; use Git worktrees instead." `tests/test_jj_retirement.py` exists to test this refusal. **This is a case where agentic-sdlc EXCEEDS pi-lab**: pi-lab has an unshippable jj branch sitting in limbo (a liability — undead code, an open decision), while agentic-sdlc has a clean, tested, one-sentence refusal doctrine with no dangling implementation. Scoping the non-feature explicitly and testing the refusal is better engineering than pi-lab's DO-NOT-SHIP branch.

## 11. Repo priming / greenfield vs brownfield / hierarchical AGENTS.md discovery

**pi-lab: DESIGNED, well-engineered, zero external exercise, score 0-1/5 on the assessment's own rubric.** `pi-agentic-sdlc-skills/skills/repo-prime/SKILL.md` (233 lines) has a real 6-phase procedure (preflight → hygiene → hierarchical AGENTS.md → ADR scaffold-only-for-real-decisions → Seeds init → gate-stack assessment with human-applied proposal → truthful verdict), a stated hard boundary ("one session cannot install its own gate"), and a documented prior false-negative calibration story. BUT: zero evidence anywhere of it authoring hygiene/ADR/AGENTS.md/Seeds into a repo pi-lab doesn't own; it was not even loaded in the assessing session despite well-formed frontmatter (an unexplained loading gap); its own `hook-resolution.sh` tool is wrong on the majority case (`core.hooksPath=/dev/null`, which holds in 5 of 9 sibling repos); Phase 2 authors a nested-AGENTS.md tree Pi cannot read back (no seed even exists whose exit condition is "nested AGENTS.md actually loads"). Greenfield/brownfield distinction itself scores literal 0 — "no code path, no skill phase, no prompt and no seed that branches on 'is this repo empty or does it have 40k lines of history.'"

**agentic-sdlc:** `commands/sdlc-init.md` is the direct analog — AGENTS.md states explicitly and self-critically: "`/sdlc-init` is a reviewed runbook, not a deterministic activation engine. It must stop on ambiguous ownership, conflicts, unsupported capability, or missing evidence; do not claim idempotence or Git-wave readiness from intent alone." This pre-emptively disclaims exactly the overreach pi-lab's `repo-prime` was caught making (claims of hierarchical AGENTS.md authority that Pi can't read back, claims of hook-resolution correctness that are wrong on the majority case). The harvest memo (§1) independently confirms: "`commands/sdlc-init.md` describes apply/receipts/deactivation the CLI doesn't support yet" is a self-flagged overclaim already recorded in agentic-sdlc's own capability matrix — i.e., agentic-sdlc's doctrine explicitly tells the reader not to trust the runbook as deterministic, where pi-lab's `repo-prime` SKILL.md does not carry an equivalently blunt disclaimer despite having the worse measured track record (zero external exercises, a majority-case-wrong tool, an unexplained non-load). **Greenfield/brownfield distinction is equally ABSENT in agentic-sdlc** — no branching logic anywhere in `commands/sdlc-init.md` or the flagship skill on repo emptiness/history size was found in this pass; this matches pi-lab's own score-0 finding and neither project has solved it.

## 12. Distribution / installability / licensing

**pi-lab: severely blocked as of the cited assessment, partially improved since.** The 2026-07-27 assessment found no LICENSE and no README at repo root and `license: UNLICENSED`. This session's direct read shows those specific findings are now STALE: a `LICENSE` file (1079 bytes) exists, `README.md` exists (175 lines, dated Aug 5), and `package.json` states `"license": "MIT"` (not `UNLICENSED`). `"private": true` still stands, which still blocks `npm publish` regardless of the licensing fix. GitHub visibility/commits-ahead-of-origin were not re-checked in this pass (network/git-mutating, out of scope).

**agentic-sdlc:** is designed from the outset as a public, installable, multi-host bundle (`scripts/install-skill-bundle.sh`, symlink installer, `bundle:install`/`bundle:status`/`bundle:uninstall` verbs already documented in AGENTS.md) — a fundamentally different distribution posture than pi-lab's private single-operator laboratory. This is not a fully comparable axis (different design goals) but agentic-sdlc's installer surface (Unix symlinks, Windows junction/copy fallback, ownership state under XDG_STATE_HOME/LOCALAPPDATA, write-command serialization) is materially more developed as *distribution* machinery than pi-lab's, which the assessment found "cannot be distributed at all today" as of 2026-07-27 (predating the README/LICENSE fixes visible now).

## 13. Seeds / issue tracking

**pi-lab: SHIPPED and the assessment's own best-scored tenet (4/5).** 259 rows (233 open/25 closed/1 in-progress) at assessment time via `@os-eco/pi-seeds`-family tooling, `sd doctor` → 12/0/0. Held below 5 only because a one-tracker-per-repo migration is owed and Seeds has never been initialized by pi-lab INTO an external repo (the install-side gap, not the tracking-side gap). `.seeds/issues.jsonl` now has 830 lines in this session's read, consistent with continued growth rather than convergence.

**agentic-sdlc:** ships the Seeds *bootstrap* mechanism itself (`skills/agentic-sdlc/tools/seeds-launcher.mjs` + the exhaustive `tests/test_seeds_launcher.py`, 877 lines / 18 adversarial tests covering exact-tuple validation, nested/dirty/untracked distribution rejection, wrong-Node rejection, hostile-ambient-config resistance) — SHIPPED and more hardened at the bootstrap-integrity layer than anything documented for pi-lab's Seeds setup. BUT per the harvest memo (confirmed unchanged in this pass): "Seeds integration is read-only: only prime/ready/blocked/--version are admitted; no lawful mutation seam (init/create/update/dep) ships, so the mission/backlog-zero doctrine in references/*.md cannot run end-to-end yet." So: agentic-sdlc's Seeds *acquisition* is more rigorously engineered (supply-chain-grade bootstrap with reproducible receipts) while pi-lab's Seeds *usage* is farther along in practice (hundreds of real tracked issues vs. agentic-sdlc's read-only-admitted operations that cannot yet drive its own mission loop end-to-end).

## 14. Self-critique / honesty culture as a transferable practice

Both projects explicitly value evidence-over-assertion doctrine, but pi-lab's own meta-audit (`assess-self-critique.md`) is the single most valuable transferable artifact in either corpus: it names its own failure mode precisely — "honesty ritual as substitute for shipping" — with a concrete remedy proposal (a "meta-delta rule": every ≥50-line audit/status update must pair with ≥25 net lines of src/test change or ≥3 closed Seeds, else it's rejected or parked to a quarterly meta-review branch). agentic-sdlc's own 12 research memos (this session totals well over 300KB of prose across 12 files, all dated 2026-08-05/06) are trending toward a comparable volume without yet triggering the same self-check — this review flags that as a live risk worth agentic-sdlc adopting pi-lab's meta-delta rule proactively rather than discovering the same pathology later. This specific transferable lesson (the meta-delta rule itself, not just "be evidence-based") is NOT currently listed as a discrete port-back item in the harvest memo's 43-item backlog — items #13/#14 (loop-design's stop-condition rule; lesson-extraction meta-skill) are adjacent but do not carry the meta-delta throughput-forcing mechanism specifically. This is a correction/addition to the harvest memo's coverage.
