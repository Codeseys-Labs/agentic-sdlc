## (1) Three most consequential gaps in this domain

1. **README.md:130 makes a false, live-falsifiable claim about plugin validation, and it is still uncommitted-unfixed.** Executed in this pass: `claude plugin validate --strict .claude-plugin/plugin.json` exits 1 with two warnings — a CLAUDE.md-at-plugin-root warning and a missing-frontmatter warning on `agents/codex/research/README.md` (confirmed via `Read agents/codex/research/README.md`: the file opens with a plain `#` heading, zero `---` frontmatter delimiters found by `rg -n "^---"`). agentic-sdlc's own `docs/research/2026-08-05-plugin-coexistence-finding.md` and `2026-08-05-plugin-restructure-recommendation.md` already documented this exact defect and proposed the fix (move the README to `docs/codex-research-roster.md`, per the judge-verdict blueprint). The smallest closing change: rename `agents/codex/research/README.md` → `docs/codex-research-roster.md` (or add a frontmatter block that marks it non-agent), fix or soften the CLAUDE.md-at-root warning (move its content into a skill per the tool's own suggestion, or accept the warning is unavoidable and correct README.md:130's overclaim to "validation is non-strict-clean, two known cosmetic warnings, tracked in issue X"), and re-run the validator to confirm exit 0 before touching the claim text.

2. **No description-byte / selection-budget gate exists, despite this being the domain's own named concern (AGENTS.md's "skill-selection-budget cost") and despite pi-lab having already built, broken, and fixed exactly this leaf (ADR-0008's byte-identity check, which caught a real two-branch collision).** `skills/agentic-sdlc/references/skill-authoring.md` Section 5 explicitly declines to publish a corpus-wide budget number, reasoning any such figure goes stale immediately — a defensible position for a *static* number, but it does not address the *generated, gate-asserted* alternative pi-lab actually shipped. The smallest closing change: add one `mise run` task (or extend `validate_bundle.py`) that sums frontmatter `description` bytes across all `skills/*/SKILL.md`, writes the total to a generated file (not prose), and asserts byte-identity between the generated file and the checked-in copy — the exact mechanism ADR-0008 describes, ported without any pi runtime dependency.

3. **Vendoring is fully designed (6 skill specs, a 21-item ranked backlog, a per-repo hyperresearch profile mechanism that resolves the model-pin blocker) and fully blocked on a missing LICENSE/NOTICE, confirmed absent in this pass (`ls LICENSE NOTICE` → no such file; `.claude-plugin/plugin.json:8` still literally says `"license": "UNLICENSED"`).** Three separate memos (vendoring memo, plugin-restructure-recommendation, judge-verdict) name this as the hard blocking prerequisite, and none of the memo-designed skills (`conventional-commits`, `technical-writing-clarity`, `mermaid-diagrams`, `adr-lifecycle`, `autoresearch-lab`, `research-claim-ledger`) exist on disk — confirmed via `ls skills/` returning exactly the same 8 directories the harvest memo baselined. Smallest closing change: land a real `LICENSE` (MIT, matching the corpus's stated intent) and a `THIRD-PARTY-NOTICES.md` stub at repo root, then flip `.claude-plugin/plugin.json`'s `"license": "UNLICENSED"` to match — this single two-file change unblocks every vendoring prescription in the corpus simultaneously; it is a pure paperwork gap, not an engineering one.

## (2) Original invention: what agentic-sdlc does that no source and not pi-lab prescribed

- **The four-plane cross-host manifest set (Claude plugin + Codex plugin + Gemini extension + bare-skills-tree for OpenCode/Goose/Kiro), unified under one symlink installer with per-host status/uninstall verbs.** Neither pi-lab's corpus nor any of the 23 external sources evaluated (mattpocock, ECC, hyperresearch, Agent-Skills format itself) prescribes shipping four separate host manifests from one skill tree — pi-lab's own scope is exactly one runtime. This is **load-bearing**: it is the mechanism by which the entire bundle claims cross-host support, verified live via `gemini-extension.json`, `.codex-plugin/plugin.json`, `.claude-plugin/plugin.json`, and the 36-test `test_run_all_hosts.py` suite (confirmed passing in this session).
- **The semantic (AST/YAML-parsed, not substring) model-pin rejection in `validate_skills`, keyed off `parse_frontmatter_metadata`.** This exact fix is *prescribed* by agentic-sdlc's own judge-verdict memo (R5) after that memo caught two independent naive proposals (from earlier memos) that would have false-positived on the skill literally named `model-tier-rightsizing`. So this is not un-prescribed — it's memo-prescribed and now confirmed landed (`scripts/validate_bundle.py:426-433`, verified via Read) — but it is agentic-sdlc's own invention relative to *pi-lab*, which has no equivalent semantic-vs-substring distinction documented anywhere in its corpus. Load-bearing: it directly gates every future skill addition.
- **The `--migrate-state --dry-run`/`--migrate-state` two-phase, non-mutating-preview-then-apply pattern for consolidating legacy install-state records into a v2 store.** No source memo or pi-lab ADR describes this specific two-phase preview/apply split for *state migration* (as distinct from PRIME's plan/apply, which is a different subsystem). This appears to be original engineering, and it is load-bearing (README.md:250-252, AGENTS.md:117-118, tested via `test_install_skill_bundle.py`).
