## (1) The three most consequential gaps in this domain

**1. The claim-ledger review-gate's substring-satisfaction defect is live, unfixed, and untested — despite the bundle's own memo having already designed the fix.**
Evidence: `skills/codex-research-os/scripts/install_research_os.py:834` gates an "important promoted claim needs adversarial review evidence" check on `not any(x in ev for x in ("adversarial", "review"))`, where `ev` is the lowercased concatenation of the claim author's *own* free-text `evidence`/`review_evidence`/`counterevidence`/`artifact_paths` fields (structurally confirmed at lines 815-841 in this session's read). Executed check in this session: the string `"adversarial review pending"` — a claim author's self-written, unreviewed assertion — contains both substrings and would satisfy the gate (`"adversarial" in ev` → `True`, `"review" in ev` → `True`). `tests/test_research_os_launcher.py` (237 lines, 13 test methods, confirmed by direct read) tests the generated dispatch-contract fields exhaustively but contains zero references to `review_gates` or `check_review_gates` — the gate's actual logic has no test anywhere in the suite. `docs/research/2026-08-05-autoresearch-lab-blueprint.md:53-260` already diagnoses this exact defect ("the highest-value change in the whole area") and designs typed obligations plus a Pilot 1 whose own subject is proving the defect it's designed to fix — but that design has not been implemented in the shipped installer.
Smallest fix: replace the four `any(x in ev for ...)` substring checks in `install_research_os.py`'s generated `check_review_gates.py` template with a typed `review_status` enum field the claim schema already half-supports (`review_status` exists in the experiment schema at line 784 but `claims.yaml` has no equivalent typed field) — a schema addition plus one generated-file template edit, no validator-surgery blast radius like the model-pin fix required.

**2. Persistent cross-session agent memory is entirely absent from agentic-sdlc, and no reference or skill even names the gap.**
Evidence: `rg -i "memory layer|persistent memory" skills/ references/` in this session returns only `codex-research-os/SKILL.md`'s "persistent memory" phrase in its own frontmatter description, which refers narrowly to the research-ledger's cross-loop `next_action.md` checkpoint (`research-team.md:62-68`), not general agent memory. Every long, deep-work-loop session in agentic-sdlc's own doctrine (`references/deep-work-loop.md`) that spans compaction boundaries has no mechanism analogous to `pi-memory-layers`' `UNREVIEWED REFERENCE`-labelled, forgery-resistant, kill-criterion-metered memory record — a worker that learns something mid-loop and is then compacted away loses it unless a human manually copies it into a Seeds issue or the mission-loop's "final checkpoint" prose step (`references/mission-loop.md:100`), which is itself DESIGNED-only (no code, no ledger, no test).
Smallest fix: this is not a small fix (it is the harvest memo's own item #5/#25 territory but for a *different* capability than what's already landed) — the smallest defensible unit is a single new `references/context-continuity.md` naming the gap explicitly and pointing at `pi-memory-layers`' `UNREVIEWED REFERENCE` label + kill-criterion pattern as the adaptation target, without yet building the mechanism (a Gate-1-through-4 admission-test candidate per `skill-authoring.md`, likely landing below the two-of-five bar for its own top-level skill and instead as a reference).

**3. Compaction-routing / cost-aware model-fallback-on-summarization has no agentic-sdlc analog at all, despite the bundle's model-tier-rightsizing doctrine being the single strongest capability in this whole comparison for *dispatch*-time routing.**
Evidence: `skills/model-tier-rightsizing/` and `references/model-routing-calibration.md` (516 lines, confirmed) rigorously solve "which model handles this dispatched unit of work" with a resolved/inherited/unresolved contract — but nothing in the bundle addresses "which model handles *compaction* when this session's context fills up," the exact problem `pi-compaction-router` solves with a cost-ordered fallback chain and a closed 5-state outcome taxonomy (`routed`/`fell-back`/`no-targets`/`aborted`/`unobserved`). Because agentic-sdlc is a host-delegated doctrine bundle (Claude Code's own compaction, not a Pi-analog extension surface), this may be a genuine category mismatch rather than a fillable gap — but the *outcome-taxonomy pattern itself* (never conflate "gate never ran" with "gate ran and failed") is portable independent of compaction and is not applied anywhere in agentic-sdlc's own gate/receipt reporting: `scripts/gate_receipt.py` (80 lines, confirmed) records only a binary `status` (exit code), with no distinct "gate never invoked" vs "gate invoked and failed" state, and the harvest memo's item #27 (which names exactly this) remains unactioned, confirmed by `rg -n "unobserved" tests/test_gate_graph.py tests/test_gate_receipts.py` → zero hits.
Smallest fix: add an explicit `"not-run"` sentinel value distinct from a `status: 1` failure to `scripts/gate_receipt.py`'s `build_receipt()` schema, and one line in `references/evidence-discipline.md`'s disposition-row discipline naming "gate never invoked" as a sixth row-type alongside not-retrieved/partial/negative-finding/staleness.

## (2) Original invention: what agentic-sdlc does that no source and not pi-lab prescribed

The **resolved/inherited/unresolved model-identity tri-state** (`references/model-routing-calibration.md:17-118`, `skills/codex-research-os/SKILL.md:70-79`) is the clearest candidate for genuine original invention in this domain. Neither `pi-memory-layers`, `pi-compaction-router`, `pi-side-chat`, `pi-lab-telemetry`, nor `pi-adaptive-thinking` describe anything resembling this contract — the closest pi-lab analog is pi-lab's own `right-sizing-design.md` three-provenance-class schema (`declared`/`mined`/`observed`), which is a *routing-qualification* concept, not an *identity-readback* concept. The tri-state's specific innovation — that a *requested* model/effort value must never silently become a *readback* value, and that `resolved` requires independent adapter-level verification rather than an echo of the request — is not present in any of the five sibling-repo READMEs read in this session, nor in `codex-research-os`'s own upstream design docs cited by this repo's memos.

**Load-bearing or speculative?** This is **load-bearing**, not speculative: it is enforced (as doctrine-consistency, not as a runtime access-control system) across every role TOML (`agents/codex/research/*.toml`, `tests/test_research_os_launcher.py:22-39`'s `RUNTIME_FIELDS` tuple lists all 16 fields and is asserted present in every generated agent), every skill's dispatch-contract language, and `SESSION-HANDOFF.md`'s recorded real incident ("three teammate agents silently downgraded" per the harvest memo, line 16) that motivated it. It is not vestigial prose — it is the one piece of doctrine in this entire domain repeated verbatim across the largest number of independently-generated files (17 role TOMLs plus the skill bodies), and its motivating incident is named rather than hypothetical.

A second, smaller invention: the **disposition-row discipline**'s explicit **staleness** class (`references/evidence-discipline.md:66`, "the fact was true against a version you can name, and may no longer hold") has no direct analog in pi-lab's evidence-discipline house skill as read in this domain's source corpus (pi-lab's version, per prior surface reports, emphasizes the 5 evidence *source* classes and the anti-inflation rule, not a *temporal decay* class on top). This is speculative rather than load-bearing today: no test in this repo enforces it (unconfirmed by direct test-suite grep in this pass), and it reads as a natural but untested extension of the ported vocabulary.

## (3) Shipped-doc-claims-capability-code-does-not-have, specific instances

1. **`skills/codex-research-os/SKILL.md`'s frontmatter description** states the skill supports "persistent memory" among its capabilities ("specialist agents, persistent memory, claim ledgers, experiment tracking..."). What is actually shipped is a per-loop `research/state/next_action.md` checkpoint file (a single resumption pointer) and a `research/claims/claims.yaml` ledger — neither of which is "memory" in the `pi-memory-layers` sense (retrievable, budgeted, precedence-ranked cross-session context injection). A reader who expects a memory *system* analogous to what `pi-memory-layers` ships would find only a checkpoint file and a claims table. This is a terminology overclaim, not a functional one — the underlying artifacts are real and tested — but the word "memory" in the description is doing more work than the shipped mechanism supports.
2. **`references/research-team.md:9`** states "The full implementation ships IN this bundle" for the 17-role research organization, immediately followed by the claim-ledger review-gate whose actual gate logic (`check_review_gates.py`, generated by `install_research_os.py`) is demonstrably satisfiable by a claim author's own unreviewed free text, as verified live in this session (finding #1 above). "Full implementation" is true of the *scaffolding* (roster, schema, workflow templates — all present and tested) but not of the *review discipline* the scaffolding is supposed to enforce, which has a known, undiagnosed-in-code, self-diagnosed-in-prose (by the bundle's own memo) defect.
3. **`skills/agentic-sdlc/SKILL.md:111` / `references/sdlc-loop.md:21`** describe HyperResearch as available for "external or load-bearing unknowns" without qualification, which reads as if the integration is wired — but no `uv tool run`/`--profile` invocation exists anywhere in the shipped tree, and the bundle's own 2026-08-06 memo (dated after this skill text was last touched) explicitly designed but has not yet landed the concrete wiring. A reader following the skill text today would find only a name-drop, not an installable, model-ID-resolved pipeline.
