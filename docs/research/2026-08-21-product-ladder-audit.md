# Product-path ladder audit — 17 open seeds vs. the shipped tree

**BLUF:** 2 close as shipped, 5 are superseded scope, 8 rescope to a narrowed remainder, 2 are still open as written. The single largest fact: **no Dynamic Workflow entry kind and no RouteQualification type exist anywhere in the tree**, and **no recorded wave journal/verdict artifact exists outside test fixtures** — so every ladder seed whose acceptance requires an *executed* installed journey is genuinely unproven, while every seed whose acceptance requires the *gateway to be mandatory* is dead by decision.

The authoritative disposition licence is `docs/plans/claude-code-first-harness/agentic-sdlc-product-spec.md:430-433` (Implementation Decision 88: "Reconcile historical PRIME/DRIVE/gateway queue records later through an authorized conductor operation without deleting history") plus `docs/plans/claude-code-first-harness/research/repository-truth-reconciliation-2026-08-15.md:105-120`, which pre-classifies four of these seeds by name (d1, g0, g2, p4) and says "Do not silently close, rewrite, or delete these records."

## PRIME lane

### `agentic-sdlc-p0` — Complete PRIME (epic) → **SUPERSEDED-BY-SPEC**
The epic's container is replaced by two named slices: **Slice 3 — Versioned lifecycle** (spec:586-591) and **Slice 4 — Activation slice** (spec:593-597), both of which shipped with executing code and tests (`scripts/ccodex_sdlc.py:41-63`, `scripts/ccodex_sdlc_install.py`, `_update.py`, `_uninstall.py`, `_recover.py`; `tests/test_lifecycle_exit_conformance.py`, `tests/test_ccodex_sdlc_install.py`, `tests/test_activation_result.py`). Its authority-boundary clause — "defines a fail-closed gateway handoff" — is void: `docs/adr/0003-gateway-stance-downgraded-to-optional.md:83-87` keeps gateways optional and never adopted CLIProxyAPI, and spec:313 (Decision 43) makes "no routed provider and an intentionally stopped gateway" a *healthy* Core state. Acceptance item 3 (fresh greenfield/brownfield installs prove apply/recovery/idempotence) is p5's whole ask; no work is lost by superseding the epic.

### `agentic-sdlc-p2` — Make activation plan/apply/recover transactional → **RESCOPE**
Almost entirely shipped, and shipped *hard*: `skills/agentic-sdlc/tools/activation-planner.py:4099-4106` exposes `plan`/`apply`/`status`/`recover {inspect,…}`; private staging, CAS publish with exact prestate, per-result readback, `effect_unknown` (24 sites in the tool, 23 in the tests) and crash-point recovery are proven by `tests/test_activation_transaction.py:175, 389, 570, 719, 2965` (4,425 lines). `agentic-sdlc-4253` records that the gate/activation family is one of only two surfaces already conforming to Implementation Decision 9's exit classes.
**Narrowed remainder (one SeedProposal):** *The activation transaction engine is scoped to ONE instruction entry per apply (`skills/agentic-sdlc/tools/activation-planner.py:6`, "Bounded Linux-only, one-entry instruction activation transaction"), and `activation-result.py` composes a terminal state from four independently produced operands rather than from one repository-level plan. ADR-0022's own Confirmation section (`docs/adr/0022-…:7`, "This decision unblocks a product-level activation compiler … Current tests cover pieces, not this complete contract") names the gap. Compile one digest-approved activation plan spanning the manifest's full entry set, so a single human grant binds the whole write set and a partial multi-entry activation is a recoverable transaction rather than N independent ones. No new engine: reuse the existing per-entry transaction as the leaf.* Maps to Slice 9's installed-byte journeys (spec:625-630) for its acceptance evidence.

### `agentic-sdlc-p3` — Managed target-local worktrees + fail-closed readiness → **RESCOPE**

**Narrowed remainder (one SeedProposal):** *Nothing executable performs the pre-creation custody preflight the ask names. `git worktree add` is a conductor recipe in prose only (`commands/sdlc-wave.md:17`, `references/worktree-lifecycle.md:47`); no product code checks that a claimed destination is under `<target>/.worktrees/`, is not a symlink/mount/special node, and is not registry-drifted, and `planning-snapshot.py` classifies neither (its 3 symlink sites are about its own output path and digesting). ### `agentic-sdlc-d3` — Target-local candidates and immutable independent reviews → **RESCOPE**

**Narrowed remainder (one SeedProposal):** *"Reviewers consume equal sealed candidate digests" is not mechanical. Bind each review/critic submission to the exact artifact-manifest digest and the snapshot head it reviewed, and make condition 4 refuse an unbound or mismatched review.* Adjacent to — not a duplicate of — open seed `agentic-sdlc-5ee7`, which is the same defect class in the *activation* composer; both want head/time linkage and should be decided together in Slice 6's residual pass.

### `agentic-sdlc-g1` — Ship the bounded Workflow overlay lifecycle → **STILL-OPEN**
Genuinely unbuilt, and the sharpest hole in the tree. The installer's entry kinds are exactly three — `{"skill": "skills", "agent": "agents", "command": "commands"}` at `scripts/install_skill_bundle.py:504, 653, 847, 1188` — with no Workflow kind, and `scripts/ccodex_sdlc_install.py` reuses those same collections (`:1169, 1513`). No Dynamic Workflow definition file exists anywhere in `plugin/`, `skills/`, or `commands/`; `commands/sdlc-wave.md` executes a wave as a conductor-driven subagent recipe. Yet ADR-0024 ("execute each wave as one artifact-driven dynamic workflow") is an **accepted** constraint (spec:434-436, Decision 89) and Decision 22 (spec:259-260) still says "One approved wave is one Claude Code Dynamic Workflow DAG".
**No slice 7-9 owns this.** It is the unclosed half of **Slice 5** (spec:599-603, "ship the smallest owned Dynamic Workflow"), and Slice 9 cannot honestly close without it: Release Validity requires "the native-Claude minimum and stable-reference Workflow canaries pass for the exact tuple" (spec:640) and Testing Decision 12-13 (spec:490-493) require Workflow canaries binding exact Claude Code version and plugin identity. Recommend restating g1 as a Slice 5 residual: one bounded `workflow` entry kind in the existing ownership/staging/durability lifecycle plus installed-versus-executed identity verification after host reload. Drop nothing else from its acceptance — foreign-overlay preservation and conflict reporting are the existing lifecycle's behavior already.

Successor container: **Slice 7** (spec:613-617).

### `agentic-sdlc-g3` — Add RouteQualification and exact dispatch admission → **RESCOPE**
Exactly half shipped, and the shipped half is the harder half. **Shipped:** RuntimeAssignment at exactly the policy-derived 16 fields with requested-vs-observed separation and pre-spawn admission — `skills/agentic-sdlc/tools/runtime-assignment.py:134` (reads the versioned policy rather than inventing vocabularies), `:348-362`, `:451`; the certified selector/effort/context tuple table is checked-in data at `skills/model-tier-rightsizing/policy/runtime-assignment-receipt-v1.json:25-29, 52-58` (exact `gpt-5.6-sol|terra|luna`, `claude-fable-5`, effort × `base`/`[1m]` tuples); 90 tests in `tests/test_runtime_assignment.py` plus 53 in `tests/test_runtime_contract_validation.py`; closed under seed `agentic-sdlc-f034`.
**Narrowed remainder (one SeedProposal):** *`RouteQualification` exists in no file in the tree — a repo-wide search finds it only in `docs/progress/2026-07-21-product-progress-snapshot.md:39, 121` and two 2026-08 research memos that already record its absence. Build RouteQualification as a distinct artifact from RuntimeAssignment (which stays at 16 fields), honouring spec Decisions 41 (30-day route freshness, 90-day mined evidence), 49 (probe ≠ qualification), 50 (independent refresh layers), 51 (default-provider fallthrough is a quarantine event), and 67/story 67 (quarantine the exact route/class cell only).* Maps to **Slice 7** (spec:613-616, "rightsizing qualification handoff, quarantine, and recovery").

### `agentic-sdlc-g4` — Prove installed routing, precedence, and refusal controls → **RESCOPE**
