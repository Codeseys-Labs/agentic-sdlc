**Date:** 2026-08-05 · **Decision:** adopt **opencodex** as the agentic-sdlc gateway candidate, under a hard configuration contract, gated on one make-or-break canary (§4). **CLIProxyAPI** = documented fallback only. **claude-code-proxy** (both variants) = rejected.

All three deep-read reports were adversarially verified against cloned source; where the verifier refuted the reader, the verifier's evidence is used below and the refutation is flagged inline.

## 2. Per-project verdict

### opencodex — **suitable as the required gateway, conditionally. Replaces both others.**
It is the only candidate that satisfies requirement (2) **as written**: the user's subscription credential is forwarded verbatim and the proxy never holds it. That is a materially different trust boundary from CLIProxyAPI's stored-token replay, and it is the difference that matters for a repo whose doctrine forbids ambient credential provenance. It also satisfies (1), (3), and (4) for plain per-request calls.

Adoption is only defensible under a **hard configuration contract**, all of which are gaps found by verification, not by the docs' happy path:
- **Never** emit a `combo/*` model ID; assert zero `combos` entries in `config.json`.
- **Never** emit a bare `claude-*` ID — always `anthropic/claude-…`, because prefix-pattern matching ignores the provider `disabled` flag while explicit `provider/model` throws.
- **Never** use `ocx-*` roster subagents (their `model` argument is inert); use plain Task subagents whose model reaches the wire in the request body.
- Assert `model_fallback` and `subagentModelFallback` are empty.
- Treat `ocx observe logs --jsonl` (`resolvedModel` / `attempts[]` / `routeDecision`) as the **only** admissible `resolved_model_id` evidence for a `RuntimeAssignment`; the response `model` field is corroborating, not authoritative.
- Do **not** run `ocx login anthropic` — that is the (a) path, which imports and stores your Claude Code token and destroys the (b) trust property.

Residual, unmitigated: 7 weeks old, no independent security review of the OAuth/passthrough paths, and class-level ToS exposure.

### CLIProxyAPI — **fallback, not the primary. Not a complement.**
Technically the most capable and by far the most battle-tested (46k★, Go binary, 13 months), and its fail-closed core is *better* than its own reader claimed. It is disqualified from primary status by two things: (i) it achieves subscription billing by **extracting, storing, and replaying** your claude.ai OAuth token rather than passing it through, and (ii) `cloak` is default-on detection evasion — an orchestrator that grades evidence cannot simultaneously ship a component whose default behavior is to misrepresent client identity to the upstream it is collecting evidence from. Its provider coverage does not exceed opencodex's, so there is no complementarity argument; keep it as the documented swap-in if opencodex's canary (§4) fails or if opencodex's youth becomes a stability blocker. If ever adopted: set `antigravity-credits: false`, `cloak.mode: never` (or `disable-claude-cloak-mode: true`), `disable-cloaking-model-list: true`, `force-mapping` off everywhere, unique `prefix:` per credential — and **do not** rely on `switch-project`/`switch-preview-model` for anything, they are dead config.

### claude-code-proxy (both `fuergaosi233` and `1rgs`) — **neither. Reject.**
Fails requirements (2), (4), (5), and (6) at the architecture level, not by configuration. 1rgs is the sharper hazard of the two: no `opus` rule means Claude Code's most common request is silently routed to Anthropic's **metered** API in default OpenAI-preference mode — the exact billing outcome requirement (2) exists to prevent — and conversion failures surface as HTTP 200 assistant text, the most silent failure mode found anywhere in this review. Add 1rgs' missing LICENSE (all rights reserved) and fuergaosi233's 5-month dormancy plus dead `MAX_RETRIES` config, and there is nothing to keep. Their one real capability — Anthropic↔OpenAI format translation — is fully subsumed by opencodex.

## 3. Single biggest unverified assumption for opencodex — **NOW VERIFIED (post-memo addendum, 2026-08-05)**

> **Addendum added by the conductor after the workflow completed.** The assumption below was checked directly against official Claude Code documentation. **Result: technically CONFIRMED, and the §4 Probe B go/no-go is already answered — but the verification simultaneously surfaced a hard ToS blocker that outranks it.**
>
> **Technical finding — subscription OAuth *is* transmitted, silently.** [llm-gateway.md](https://code.claude.com/docs/en/llm-gateway.md), "Subscriptions and gateways": *"Setting only that variable, without a gateway credential, doesn't replace the subscription. Requests still route through the gateway, but a saved claude.ai login remains the active credential, so its usage limits and billing apply. Gateways that pass this traffic on to Anthropic must forward the OAuth capability in `anthropic-beta`."* Corroborated by [gateways.md](https://code.claude.com/docs/en/gateways.md) and by the authentication precedence list ([authentication.md](https://code.claude.com/docs/en/authentication.md) item 6: subscription OAuth is the fallthrough default when no cloud/gateway credential is set). [llm-gateway-protocol.md](https://code.claude.com/docs/en/llm-gateway-protocol.md) adds an operational requirement the memo missed: the `anthropic-beta` header carries an **OAuth capability that the upstream requires — stripping it fails those requests with 401**, and Claude Code "never suppresses" it. So opencodex's passthrough must preserve `anthropic-beta`, not just `authorization`.
>   - The docs contradict the memo's opposing quote: gateway mode and subscription mode are **not** mutually exclusive; they become exclusive only once a gateway credential *is* set, at which point *"the credential replaces the subscription login for that session, and the subscription's usage limits don't apply"* — billed per token to the credential owner.
>   - Docs are silent on the `sk-ant-oat01-*` token string format and on which exact header carries OAuth in this configuration, so opencodex's `sk-ant-` prefix gate remains empirically unverified (Probe A still worth running).
>   - Also documented: a non-Anthropic base URL silently disables Remote Control (v2.1.196+), MCP tool search, and fine-grained tool streaming. That is a capability cost the memo did not price in.
>
> **Blocking finding — Anthropic's stated policy prohibits this exact use.** [legal-and-compliance.md](https://code.claude.com/docs/en/legal-and-compliance.md), "Authentication and credential use": OAuth is *"intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications"*; developers *"should use API key authentication"*; *"Anthropic does not permit third-party developers to offer Claude.ai login or to route requests through Free, Pro, or Max plan credentials on behalf of their users"*; *"Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."* [Consumer Terms](https://www.anthropic.com/legal/consumer-terms) (eff. 2025-10-08) §2 forbids sharing account credentials, and §3's automated-access carve-out is **API-key-scoped only** — subscription OAuth does not qualify. Same page also states the plain support posture: *"Anthropic doesn't endorse, maintain, or audit third-party gateway products, and doesn't support routing Claude Code to non-Claude models through any gateway."*
>   - Narrow honesty: the "on behalf of their users" clause is written at third-party-developer scope, so a strictly single-operator personal loopback proxy is not literally inside that sentence — but it is still outside the "exclusively … native Anthropic applications" scope in the same bullet and still lacks the §3 API-key carve-out.
>
> **What this means for the decision.** The §1 matrix row (2) stands: opencodex is the only candidate that achieves subscription billing by true passthrough. But the memo's framing — that requirement (2) merely carries "class-level ToS exposure" — understates it. The *supported* way to put a gateway in front of Claude Code is an explicit gateway credential, which by design bills per token and **eliminates the cost-efficiency premise this whole evaluation was built on.** The architecture works; the authorization does not. Per AGENTS.md, "a passing canary is evidence only" — and here the evidence is that the mechanism functions while the policy forbids it. **This is a decision for you, not a technical gate**, so §4 stays unrun pending your explicit call; see the conductor's summary for the three framed options.

**Original (now-verified) assumption text, retained for the record:**

**That Claude Code, with `ANTHROPIC_BASE_URL` pointed at a loopback gateway and `ANTHROPIC_AUTH_TOKEN` left unset, actually transmits its own subscription OAuth bearer (`sk-ant-oat01-*`) to that non-Anthropic base URL.**

Everything about requirement (2) hangs on this, and **no report verified it from Claude Code's side.** It is inferred from opencodex's docs plus the existence of the `sk-ant-` gate. The opposing evidence is in opencodex's own prose: *"Claude Code needs a token in `ANTHROPIC_AUTH_TOKEN` to talk to a gateway, but setting that variable also disables your claude.ai login"* — which is a statement that Claude Code treats gateway mode and subscription mode as mutually exclusive. If Claude Code withholds its OAuth credential from a custom base URL (or refuses to start without `ANTHROPIC_AUTH_TOKEN`), the deployment collapses into auto mode's other branch, where the injected placeholder is literally `opencodex-proxy` — which **fails the `sk-ant-` gate**, so genuine `claude-*` requests are *translated/routed* instead of passed through. That outcome is worse than a hard failure: subscription billing silently stops applying and `claude-*` traffic lands wherever the routing chain sends it.

Secondary, related: the auth-mode detector counts an exported `ANTHROPIC_API_KEY` as "a Claude login," so a stray env var yields "subscription mode" while actually billing metered — and nothing in either codebase reads a plan/entitlement field, so "Pro/Max subscription" is an inference from OAuth client + scope in *both* projects, never a verified fact.

## 4. Concrete next validation step — opencodex canary

Blast radius includes real provider credentials and real account-standing risk, so per `AGENTS.md` this needs **explicit operation-specific user authorization before step 2**, and a throwaway/secondary Anthropic account if one is available. Run everything under an isolated `HOME`; make no persistent `mise trust`, shell-alias, or global-config mutation.

```bash
# --- 0. Isolate. Nothing persistent, nothing global.
export CANARY=/tmp/ocx-canary && mkdir -p "$CANARY"/{home,ocx,logs}
export HOME_REAL="$HOME"

# --- 1. Baseline: prove the account is subscription-authed BEFORE any proxy exists.
claude          # run /status ; record verbatim: auth source + plan + model id
# Record whether any ANTHROPIC_API_KEY / ANTHROPIC_AUTH_TOKEN is exported anywhere:
env | grep -i anthropic     # MUST be empty, or the auth-mode detector lies to you

# --- 2. Install opencodex isolated. Do NOT run `ocx login anthropic`
#        (that is mechanism (a): it imports and stores your Claude Code token).
env HOME="$CANARY/home" OPENCODEX_HOME="$CANARY/ocx" \
  npm install -g --prefix "$CANARY/npm" @bitkyc08/opencodex
env HOME="$CANARY/home" OPENCODEX_HOME="$CANARY/ocx" "$CANARY/npm/bin/ocx" serve &

# --- 3. Contract assertions BEFORE any traffic. All four must be empty/absent.
jq '.combos, .routing.subagentModelFallback, [.agents[]?.model_fallback]' "$CANARY/ocx/config.json"
jq '.providers[] | select(.disabled==true) | .name' "$CANARY/ocx/config.json"

# --- 4. Attach the ONLY admissible readback source.
env OPENCODEX_HOME="$CANARY/ocx" "$CANARY/npm/bin/ocx" observe logs --follow --jsonl \
  > "$CANARY/logs/ocx.jsonl" &
```

**Probe A — prove the `sk-ant-` gate is real (negative control).**
`curl -s localhost:10100/v1/messages -H 'authorization: Bearer <A-DELIBERATELY-INVALID-NON-SK-ANT-TOKEN>' -H 'content-type: application/json' -d '{"model":"anthropic/claude-opus-5","max_tokens":16,"messages":[{"role":"user","content":"hi"}]}'`
(the token is a negative control — it must NOT start with `sk-ant-`. Written as a placeholder here so the secrets scanner's `curl-auth-header` rule does not flag this memo.)
Expect: **not** a native-passthrough log line. If `routeDecision` says passthrough, `claude-messages.ts:97-101` is not behaving as verified — stop.

**Probe B — THE make-or-break test (§3).** With `ANTHROPIC_BASE_URL=http://localhost:10100` and `ANTHROPIC_AUTH_TOKEN` **unset**, run `claude -p "reply with only your exact model id"`. Then in `ocx.jsonl` confirm, for that request: inbound credential prefix is `sk-ant-oat01`, upstream host is `api.anthropic.com`, and the route is native passthrough with the model unrewritten. **Go/no-go:** if the inbound credential is `opencodex-proxy` or absent, or Claude Code refuses to start / prompts for login → **NO-GO on requirement (2)**; stop and re-open the decision (fallback = CLIProxyAPI, or split-plane: direct Anthropic for Claude, gateway for non-Claude only). Then re-run `/status` and check claude.ai usage to confirm the call consumed **subscription** quota, not API credit.

**Probe C — fail-closed, explicit route.** Configure one non-Anthropic provider with a deliberately invalid credential; request its exact `provider/model`. Expect a hard error. Repeat with that provider `disabled: true` → expect a throw. **Any `claude-*` answer to a non-Anthropic request = NO-GO on (5).**

**Probe D — the prefix-pattern hole.** With the `anthropic` provider `disabled: true`, request bare `claude-opus-5` (no `anthropic/`). If it still routes (as [guides/model-routing](https://opencodex.me/guides/model-routing/) admits it does), the contract "never emit bare model IDs" becomes **mandatory and must be enforced in the RuntimeAssignment validator**, not documented as advice.

**Probe E — per-subagent pinning under concurrency.** Two plain Task subagents (no `ocx-*` roster), one pinned `anthropic/claude-…`, one pinned an exact non-Anthropic ID, dispatched concurrently. Reconcile each response body `model` against its `ocx.jsonl` `resolvedModel`/`attempts[]`. **Any cross-talk or any `attempts[]` length > 1 = NO-GO on (4)/(5).**

**Probe F — readback admissibility.** Capture response headers for all probes (`curl -D -`) and confirm no provider/model header exists (expected: none). Then decide explicitly whether `ocx observe logs --jsonl` correlation satisfies the doctrine's "resolved only after adapter readback" bar. If it does not, requirement (6) is **unmet by every candidate reviewed** and the orchestrator needs either an upstream PR adding an `x-opencodex-resolved-model` response header, or a documented downgrade of that RuntimeAssignment field to `unresolved` for gateway-routed models.

**Teardown:** kill both background processes, `rm -rf "$CANARY"`, re-verify `env | grep -i anthropic` is clean, confirm no writes landed under `$HOME_REAL/.claude` or `$HOME_REAL/.codex`.

Ship/no-ship gate: **all of A–F must pass, with B and E as absolute blockers.** A passing canary is evidence only — it does not authorize making the gateway the default for any outward-effect operation.
