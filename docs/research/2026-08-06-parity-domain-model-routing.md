## (1) Three most consequential gaps in this domain

1. **No populated, operated route ledger inside agentic-sdlc.** agentic-sdlc's `model-routing-calibration.md` reproduces pi-lab's exact three-rung/three-provenance vocabulary almost verbatim (`catalog-only`/`route-probed`/`role-qualified`; `declared`/`mined`/`observed`) but nothing in `skills/model-tier-rightsizing/` maintains a live data file analogous to pi-lab's `docs/route-ledger/route-ledger.json` (957 lines, populated with real `route-probed-positive`/`negative` entries, verified via `rg -c "\"status\""`). Without an operated ledger, the `resolved`/`inherited`/`unresolved` contract (agentic-sdlc's genuine strength) has nothing concrete to resolve *against* at the route-provenance layer — it enforces the shape of a receipt but not a corpus of qualified routes. Smallest fix: add one `policy/route-ledger-v1.json` seeded from the calibration doc's own worked example (line 499) plus a JSON Schema modeled on pi-lab's `route.schema.json`, and one test asserting new entries can only reach `route-probed`/`role-qualified` via cited evidence (directly portable from `route.schema.json:85-136`).

2. **The gateway-mandatory ambition is stated only in uncommitted files and contradicts committed doctrine, unresolved.** Verified live: `rg -ni gateway AGENTS.md README.md` returns zero hits in the committed tree, yet `SESSION-HANDOFF.md:65,79,96` and the uncommitted `docs/progress/2026-07-21-product-progress-snapshot.md:34,81,115,151` state "gateway-owned execution" is the next required milestone and self-flag the contradiction against README's provider-native baseline (progress-snapshot line 81). Meanwhile the repo's own gateway-selection-memo's post-hoc addendum found the cost-saving premise (subscription-OAuth passthrough) is ToS-blocked, and pi-lab's independently-derived PROVIDER-REACH VERDICT concludes no gateway is needed at all. Smallest fix: either commit an explicit downgrade of "gateway mandatory" to "gateway optional, ToS-blocked for subscription-cost use case" into AGENTS.md (the memo's own conclusion already supports this one-paragraph edit), or delete the aspiration from SESSION-HANDOFF.md/progress-snapshot until a human ruling is recorded — right now the aspiration is a live, self-diagnosed but unrepaired doctrine fork inside the working tree.

3. **A real, tested gateway-qualification harness and a real Bedrock-routing extension already exist in the ecosystem but are not wired into agentic-sdlc's installable surface.** `bedrock-mantle-frontier-bundle/config/gateway.qualification.example.yaml` (60 lines) is exactly the credential-scrubbed, ephemeral, single-route CLIProxyAPI qualification template the gateway-selection-memo's Probes A-F ask an operator to hand-build; `pi-bedrock-mantle/extensions/mantle/*.ts` (1,026 lines, 34 tests across 9 files including adversarial guards `no-unverified-widening.test.ts` and `no-self-audited-retention-lint.test.ts`) is a real, executable Bedrock model-routing extension with catalog/classify/disclose/observe/routes modules. Neither is referenced from `skills/agentic-sdlc/` or `skills/model-tier-rightsizing/`. Smallest fix: add one `references/gateway-qualification-harness.md` pointer in `skills/repo-toolchain-gates/` or `skills/model-tier-rightsizing/` citing the exact qualification-YAML pattern and the mantle extension's guard-test pattern (`no-unverified-widening`, `no-self-audited-retention-lint`) as adoptable templates — this closes a real "reinventing a wheel that already exists two directories over" gap without requiring any new gateway code to be written from scratch.

## (2) Original invention — not prescribed by any source, not built by pi-lab

- **The `resolved`/`inherited`/`unresolved` tri-state for model *identity* specifically (as opposed to route qualification)** is agentic-sdlc's own invention. No source memo, ADR, or pi-lab file uses this exact vocabulary for model-identity resolution; pi-lab's `driven-agents.md` explicitly admits the analogous auth-precedence problem is unsolved ("no reviewed package does automatically — this must be added, not assumed" per SOURCES pi-lab). **Load-bearing**: it is mechanically enforced (`receipt_admission.py`, 41 tests) and is the field the rest of the doctrine (AGENTS.md's entire model-routing paragraph) is built around. This is agentic-sdlc's strongest, most defensible original contribution in this domain.
- **The requirement that "requested values never become readback"** (AGENTS.md:94-95, mechanically enforced via `receipt_admission.py`'s evidence-status enums) is a sharper, more explicit anti-conflation rule than anything in the source corpus — the gateway-selection-memo's Probe F identifies the *problem* (no candidate gateway satisfies a readback bar) but does not itself invent the rule that a request must never silently become its own proof; agentic-sdlc's policy states and enforces exactly that. **Load-bearing**, not speculative — it is the mechanism that would catch a gateway silently promoting a request echo to a verified readback if one were ever wired in.
- **Byte-frozen Node/Bun version pinning tied to the same "certified tuple" doctrine as model routing** (`seeds-launcher.mjs` refusing Node 26 at runtime, verified live) is original to agentic-sdlc; no pi-lab or gateway-memo source ties toolchain-version pinning into the model-routing trust chain this explicitly. **Speculative-adjacent**: it protects Seeds bootstrap integrity, and its connection to model-routing trust is more a shared "certified tuple" *philosophy* than a direct mechanism — worth flagging as elegant but not load-bearing for routing itself.
